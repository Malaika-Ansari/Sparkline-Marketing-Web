### 1. Overview

The Sparkline Marketing platform exposes private API endpoints through a hardened server middleware (`src/server/ai-proxy-middleware.ts`). These endpoints mediate interactions with AI models, external SEO crawl targets, exchange-rate financial services, and database persistence.

This document outlines the security controls, validation filters, rate-limiting rules, and defense-in-depth mechanisms applied across all API endpoints.

### 3. Endpoint Security Specifications

#### 3.1 Rate Limiting Architecture
- **Window Size**: 5 minutes (`300,000 ms`).
- **Maximum Requests**: 10 requests per window per IP address.
- **Exceeded Response**: HTTP 429 Too Many Requests with JSON payload:
  ```json
  {
    "ok": false,
    "error": "RATE_LIMIT_EXCEEDED",
    "message": "Too many requests from this IP. Please wait a few moments before trying again."
  }
  ```

#### 3.2 Request Size Restrictions
- All POST endpoints enforce a hard **2MB payload limit**.
- Any request exceeding 2MB is aborted immediately before in-memory JSON parsing, preventing Denial-of-Service (DoS) and heap exhaustion attacks.

#### 3.3 Security Response Headers
Every JSON response generated by the server proxy includes:
```http
Content-Type: application/json
X-Content-Type-Options: nosniff
X-Frame-Options: SAMEORIGIN
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: camera=(), microphone=(), geolocation=()
Cache-Control: no-store, max-age=0
```

#### 3.4 Safe Error Handling & Information Leakage Prevention
- Internal database connection errors, stack traces, and Node.js environment paths are **never** returned to the client.
- Outward error messages use deterministic domain codes (`INSUFFICIENT_PROJECT_DATA`, `AUDIT_EXECUTION_ERROR`, `RATE_LIMIT_EXCEEDED`).
- All unexpected exceptions are caught and sanitized before response dispatch.

### 4. Defense Against Mass Assignment

- Frontend clients cannot submit arbitrary fields that override authorization state.
- In `saveProject()`, critical ownership fields (`userId`, `createdAt`) are bound on the server or resolved from the existing database record:
  ```typescript
  const projectToSave: MarketingProject = {
    ...project,
    userId: existing?.userId || project.userId || userId,
    updatedAt: new Date().toISOString(),
  };
  ```
- Submitting a modified `userId` in the payload has zero effect on ownership.

---

### 5. CORS and Cross-Origin Safeguards

- Development and preview servers bind strictly to the application origin.
- External scripts cannot invoke private API routes cross-origin due to standard browser same-origin policy enforcement and strict CORS preflight checks.
